# Проверка GitHub-AI-MCP — 13 октября 2026

## Вывод по вашему случаю

В коде найдены реальные проблемы настройки и диагностики. По присланным данным нельзя считать туннель исправным: локальный HTTP MCP работает, но процесс tunnel-client не запущен.

На скриншоте YAML команда начинается с `uv run python -m github_ai_mcp`, а окно собранного приложения показывает команду `GitHub-AI-MCP.exe --internal-server ...`. Функция `preflight()` сравнивала строки буквально и при несовпадении возвращала MCP_COMMAND **до запуска процесса**. Сообщение на вашем скриншоте прямо соответствует этой ветке. Поэтому `process_alive: false`, `pid: null`, `retries: 0` согласуются с локальной блокировкой запуска, а не доказывают сетевую проблему.

При этом кнопка исправления зависела от успешного doctor и доступа к ключу. Если любая из этих проверок не проходила, новая команда вообще не записывалась. Это подтверждённый дефект кода; какая именно проверка срывала ваши прошлые попытки, без журнала установить нельзя.

Поле stdio было явно помечено `setReadOnly(True)`. Это не ошибка ввода с вашей стороны: программа действительно запрещала его менять.

- Разобраны ключевые пути: загрузка конфигурации, GUI и обработчики кнопок, запуск/остановка/повторный запуск процессов, stdio, HTTP, YAML, хранилище ключей, автозагрузка, PyInstaller и упаковка.
- Дополнительно рассмотрены Git-операции, проверки путей и секретов, политика разрешений, SQLite, состояние заданий, публикация и восстановление. Тесты этих подсистем включены в общий запуск.
- Проверены четыре присланных скриншота и исходный ZIP. Приложение на вашем компьютере не изменялось.

Добавлены регрессии для фактического редактирования и сохранения через GUI, локального исправления без клиента/ключа, проверки с несохранённым ключом, структуры YAML, безопасного кода ошибки, очистки процесса и состава архива.

## Результаты проверки

Исходный архив: 157 passed, 8 failed за 28,31 с. Все восемь падений связаны с импортом scripts; это не объясняет ошибку туннеля, но мешает проверке проекта.

Исправленная версия: **180 passed за 31,89 с**. Команда: `QT_QPA_PLATFORM=offscreen uv run pytest -q`. Использовано зафиксированное окружение из uv.lock.

Ruff: ошибок нет. Mypy: ошибок нет в 35 исходных модулях с параметрами `--no-incremental --no-native-parser -n 0`. Стандартный native-parser mypy в этой среде завершался внутренней ошибкой psutil при определении PID; зависимости проекта из-за этого не заменялись.

Локальный демонстрационный сценарий завершился успешно: пять файлов → пять коммитов → публикация в временный локальный bare-репозиторий. Реальных отправок в GitHub не выполнялось.

## Что ещё не подтверждено

- Запуск собранного Windows EXE, работа Windows Credential Manager, Job Objects и HKCU Run на вашем ПК. В этой среде Linux; Windows-специфичные тесты с подменами не заменяют реальный запуск.
- Конкретная версия и бинарник tunnel-client: в исходном архиве vendor отсутствует. Поддержку его аргументов, поведение doctor и облачное подключение нужно проверить на установленном клиенте.
- Действительность runtime key, доступ к tunnel ID, сеть и состояние сервиса провайдера. Локальное исправление команды не гарантирует успешную авторизацию.
- После исправления MCP_COMMAND может проявиться следующая независимая ошибка. Теперь её код будет в копируемой диагностике.

Проверка не является гарантией отсутствия всех возможных ошибок. Подтверждены исправления перечисленных сценариев и результаты запусков, указанные в этом отчёте.

## Как применить

1. Закройте старое приложение через «Закрыть приложение». Если клиент запущен отдельно из терминала, остановите именно его там.
2. Используйте исправленные исходники из этого архива и пересоберите EXE по docs/RELEASE_BUILD.md. Существующие vendor-бинарники нужны для сборки; их нет и не было в присланном ZIP. Существующую папку данных и YAML удалять не нужно.
3. Запустите новый EXE. В настройке запуска выберите существующий клиент и нужный YAML.
4. Нажмите «Подставить команду текущей программы», затем «Исправить команду MCP». Должно появиться сообщение об успешной записи и путь резервной копии. Интернет и ключ для этого шага не нужны.
5. Введите runtime key туннеля в поле пароля, если он ещё не сохранён. Нажмите «Сохранить». Команда, заданная ранее только в PowerShell, не импортируется в хранилище автоматически.
6. Откройте настройку и нажмите «Проверить профиль и ключ», затем запустите туннель в разделе служб. Работающий HTTP MCP и успешное подключение туннеля — отдельные проверки.
7. Если запуск не прошёл, скопируйте безопасную диагностику: теперь она содержит error_code и exit_code. Сам ключ присылать не нужно.

В архиве исходники, а не готовый исправленный Windows EXE. Старый уже собранный EXE не изменится от одной замены исходных файлов.
