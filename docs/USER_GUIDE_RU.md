# GitHub-AI-MCP 1.0.1 — запуск Windows и туннеля

## Запуск и сборка

Готовое приложение запускается одним `GitHub-AI-MCP.exe`. Python пользователю
не нужен. Настройки и журналы хранятся в `%LOCALAPPDATA%\GitHub-AI-MCP`.
Этот архив содержит исходники, EXE здесь не собран. Подготовка бинарников
и сборка описаны в [RELEASE_BUILD.md](RELEASE_BUILD.md).

## Настройка один раз

1. Остановите старую программу через её меню выхода. Внешний tunnel-client,
   запущенный из PowerShell, остановите в том окне. Новое приложение его не завершает.
2. Откройте новый EXE → настройку запуска. Git и GitHub CLI проверяются в этом окне.
   Для локальных функций туннель необязателен. GitHub PAT вводите только при необходимости.
3. Используйте встроенный `tunnel-client.exe` (или явно выберите другой официальный клиент) и существующий файл профиля YAML кнопками выбора.
   Профиль создаётся официальным клиентом для вашего действующего tunnel ID;
   приложение не создаёт облачный туннель и не выдаёт доступ к аккаунту.
4. Введите runtime control-plane API key туннеля в поле пароля. Это отдельный ключ:
   GitHub PAT, ключ модели OpenAI и токен локального MCP не подходят.
5. Включите «Запускать при входе в Windows», «Запускать службы при открытии» и
   нужные службы MCP/туннеля. При желании включите сворачивание в трей,
   восстановление после сбоя и уведомления. Нажмите «Сохранить».
6. Снова откройте настройку. Нажмите «Подставить команду текущей программы», затем
   «Исправить команду MCP» и подтвердите изменение. Нажмите «Сохранить».
   Исправляется только команда канала main, сохраняется резервная копия. Ключ и сеть
   для исправления не нужны. Поле stdio можно редактировать; своя команда применяется
   к выбранному YAML при сохранении настройки.
   Затем нажмите «Проверить профиль и ключ». Проверка doctor может занять до 25 секунд.
7. Запустите службы на экране служб. Локальный HTTP MCP и stdio-сервер туннеля
   независимы: зелёный статус первого не доказывает работу второго.

Ключ хранится в Windows Credential Manager текущего пользователя. При следующем
входе он считывается автоматически и передаётся только окружению дочернего клиента.
Не требуется каждый раз открывать PowerShell или задавать переменную вручную.
Ключ не записывается в JSON, YAML или команду автозапуска и не показывается повторно.
Чтобы заменить его, введите новый и сохраните. Для удаления есть отдельная кнопка.
Приложение не импортирует ключ из прежнего PowerShell автоматически.

## Профиль и ошибки YAML

Укажите точный YAML через кнопку выбора; это устраняет неоднозначность расположения
профилей разных версий клиента. Поле `control_plane.api_key` должно содержать ссылку
`env:CONTROL_PLANE_API_KEY`, а не сам ключ. Профиль должен иметь одну команду stdio main.
Поддерживаемая схема проверяется установленным клиентом, а не самодельной схемой.

Кнопка «Редактор YAML» позволяет исправить синтаксис. Перед сохранением выполняется
локальная проверка структуры и команды; неправильный результат не заменяет файл.
Проверка doctor выполняется отдельно и перед запуском туннеля. Создаются резервные копии,
запись атомарная. Литералы секретов маскируются; замените их на безопасные ссылки.
Резервная копия повреждённого профиля также маскируется и может не быть точной копией.
Исправление команды валидного профиля сохраняет исходную копию и остальные настройки.

Если doctor отклонил профиль или ключ, приложение останавливает повторы: проверьте
диагностику официального клиента, сеть, права runtime key и срок его действия.
При тайм-ауте или неожиданном завершении выполняются не более трёх повторов с задержкой.
Ручной «Запуск» начинает новую попытку после исправления причины. Ошибка exit 2 и
обнаруженное отклонение авторизации не вызывают бесконечных перезапусков.

## Что означает статус

| Статус | Значение и действие |
|---|---|
| MCP работает | Проверены локальный токен, PID и идентификатор своего сервера |
| Процесс туннеля работает, соединение не проверено | Есть процесс; удалённая доступность не доказана |
| Есть свежие локальные подтверждения | Клиент сообщил недавние успешные наблюдения MCP/control-plane; это не удалённый вызов ChatGPT |
| Внешний процесс, не управляется | Найден выбранный исполняемый файл вне супервизора; остановите его в исходном приложении |
| Повторный запуск | Ожидание ограниченной повторной попытки |
| Нарушена работа | Клиент сообщил деградацию компонента |
| Ошибка | Проверьте сообщение и журнал служб; исправьте ключ, профиль, путь или конфликт порта |

Проверка готовности клиента сама по себе не подтверждает обмен MCP.
Старые клиенты, неизвестная схема health или недоступные сведения о процессе
отображаются без утверждения об исправном соединении. Для реальной проверки
в ChatGPT подключите ваш туннель и вызовите read-only health_check и list_repositories.
Публичные адреса и доступ к репозиториям автоматически не создаются.

«Диагностика» и «Копировать диагностику» выдают статусы и ограниченные наблюдения,
без содержимого профиля, ключей и сырого stderr. Локальные журналы служб редактируются
для скрытия известных секретов. Не пересылайте необработанные журналы самого клиента.

## Автозапуск, обновление, удаление

«Проверить автозапуск» показывает фактическое состояние регистрации Windows.
Используется одна запись текущего пользователя; прав администратора не требуется.
«Включить / исправить» работает только после включения соответствующего флажка.
«Открыть автозагрузку Windows» открывает системные настройки.
Для выключения снимите флажок и сохраните. Запуск служб при открытии настраивается отдельно.
При наличии старого ярлыка GitHub-AI-MCP в папке автозагрузки сначала удалите именно
этот старый ярлык: программа сообщает конфликт и не создаёт конкурирующую регистрацию.

После перемещения папки: откройте приложение из нового места, исправьте регистрацию
автозапуска и команду MCP профиля. Не удаляйте `.venv` при работе из исходников;
после переноса исходников повторите установку зависимостей. У готового EXE такой зависимости нет.

При закрытии в трей сбор продолжается; для полного завершения используйте «Выход».
Одновременный второй GUI блокируется существующей блокировкой контроллера.
Чужие процессы и занятые ими порты приложение принудительно не освобождает.

Перед удалением portable-версии отключите автозапуск, при желании удалите ключ туннеля,
завершите программу и удалите её папку. Установщик удаляет собственную регистрацию
автозапуска, но сохраняет конфигурацию, репозитории и пользовательские ключи.
Разрешения репозиториев, grants и READ_ONLY/LOCAL_REVIEW/AUTO_APPROVED не расширяются.

## Что ещё проверить на вашем Windows

Проверить готовые EXE, настройку ключа в реальном Credential Manager, вход после
перезагрузки, трей, восстановление при недоступной сети, перенос папки и удаление.
Реальное соединение вашего туннеля в этой среде не проверено. Нативные проверки описаны в WINDOWS_SMOKE_TEST.md.
